# WebView 票据与位置接入设计

日期：2026-09-28

## 目标与范围

本设计为团队内部复制的 Taro React 小程序模板增加可复用 WebView 接入能力。复制项目登记可信网页后，已登录用户可以从小程序打开该网页；网页通过一次性票据向本仓库的 NestJS API 换取专用 JWT，再读取有限的用户资料。用户主动选择携带位置时，小程序把 GCJ-02 经纬度作为 URL 参数传给网页。用户拒绝定位或定位失败时，网页仍正常打开，且 URL 不含坐标。

首版只支持微信小程序，不引入多租户、WebView 管理后台、网页专用刷新会话或业务数据接口。网页所需商品、订单等业务数据仍由复制项目的业务模块定义。WebView JWT 过期后，用户从小程序重新进入网页。

## 接入方案

选择服务端一次性票据方案。直接把小程序访问令牌或 WebView JWT 放进 URL 会让可复用令牌暴露在浏览器历史和网页资源请求中；依赖小程序与网页的消息桥传递身份又无法稳定覆盖网页初次加载。因此小程序只把短时、单次使用的 ticket 放进 URL，网页加载后立即兑换，并从地址栏移除 ticket。

复制项目通过服务端环境变量 `WEBVIEW_APPS_JSON` 登记固定应用列表，每项包含公开的 `appId`、显示名称、入口 URL 和允许的网页来源。`appId` 是应用标识，不是密钥。启动时校验标识唯一、入口 URL 与允许来源一致；正式地址必须是 HTTPS。本地开发允许显式配置 HTTP loopback 地址。小程序不能提交任意网页 URL，服务端只为已登记应用签发票据并返回其入口地址。微信后台仍需配置对应业务域名；正式域名和 HTTPS 由部署项目提供。

服务端提供 `GET /webview/apps`，只返回可展示的应用标识和名称，供小程序入口列表使用；不返回 JWT、票据或内部配置。没有登记应用时，入口页显示配置说明，不构造任意网页地址。

## 打开与兑换流程

1. 能力中心进入像素风“网页应用”页，展示服务端登记的应用。用户点选应用并决定是否携带当前坐标。尚未登录时先跳转既有微信登录页，登录完成返回网页应用页，由用户再次点选。不会在页面加载时静默定位。
2. 选择携带坐标时，调用现有一次定位能力。成功后仅把 `latitude`、`longitude` 和 `coordinateSystem=gcj02` 加入本次目标 URL；拒绝、取消、不可用或失败时均省略全部坐标参数并继续。页面告知用户坐标将交给目标网页。坐标只在本次打开流程中使用，不写入数据库或埋点。
3. 定位步骤结束后，小程序凭现有登录态请求 `POST /webview/tickets`，请求体只含 `appId`。服务端生成不可预测的高熵 ticket，存储其 SHA-256 哈希、用户 ID、应用标识、到期时间和消费时间；原文只在响应中返回一次。票据有效期 60 秒。小程序将 `appId`、`ticket` 和可选坐标合入服务端返回的入口 URL，保留入口已有的合法查询参数及片段，再用 Taro `WebView` 打开。
4. 网页加载后先读取 `appId` 和 `ticket`，立刻用 `history.replaceState` 从地址栏移除 ticket，再向 `POST /webview/exchange` 提交两者。服务端校验应用、票据哈希、有效期与未消费状态，并原子标记已消费；重复兑换、过期或跨应用兑换均失败。成功时签发 15 分钟的 WebView JWT，包含用户 ID、固定的 WebView 用途声明及应用 audience。示例网页将 JWT 仅保存在当前页面内存；重载或到期后提示从小程序重新进入。
5. 网页用 `Authorization: Bearer` 请求 `GET /webview/me`，只获得 `id`、`nickname`、`avatarUrl` 和 `phoneBound`。头像 URL 沿用私有 OSS 的短期签发地址；不返回手机号、微信 openid、刷新令牌或小程序原生访问令牌。

坐标 URL 参数可被网页用户修改，因此只是业务输入，不能用于身份认证、授权或支付判断。入口 URL、网页内容和其业务行为由复制项目负责。示例网页只演示兑换、资料读取与坐标展示。

## 身份与浏览器边界

现有小程序访问 JWT 与 WebView JWT 使用同一签发密钥，但必须具有不同的用途声明。小程序的 `AccessGuard` 只接受小程序用途；新的 WebView Guard 只接受 WebView 用途、有效的应用 audience 和未过期令牌。WebView JWT 不得访问现有 `/users/me`、文件、支付等小程序接口；后续业务接口若允许网页访问，须显式采用 WebView Guard 并检查其应用标识。

服务端仅对已登记网页来源启用精确 CORS 允许列表，不使用通配符。浏览器来源校验不是票据认证的替代：票据仍需满足一次性、短期、应用绑定条件。服务端请求日志、错误响应及小程序埋点不记录 ticket、JWT、完整 URL、坐标或用户资料。对外失败信息不区分票据不存在、过期和已消费。

票据使用现有 PostgreSQL 和 Prisma，新建一张票据表，不建立第二个数据库。每次签发新票据时清理过期或已消费票据；清理不会影响兑换的原子性。

## 页面与本地示例

小程序新增独立 WebView 列表页和承载页，并在现有能力中心添加入口。承载页仅接受已登记的 `appId`，不会从页面参数直接读取网页 URL。打开失败留在小程序页并显示可重试提示。视觉沿用“轻购实验室”的像素风，原有门户和登录流程只改动必要的路由衔接。

仓库附一个最小示例 H5，由现有 NestJS API 的 Docker 镜像提供静态页面，不新增运行中的服务或数据库。复制项目可移除示例，只保留票据接口和接入说明。示例只展示兑换结果、有限用户资料和收到的坐标；它不发起订单、支付或其他业务请求。本地开发可用 HTTP loopback 示例地址与微信开发者工具联调；真机和正式部署需要公网 HTTPS、微信业务域名配置及相应的 API 可达性。

接入文档给出服务端应用配置样例、WebView URL 参数、兑换与资料接口示例、JWT 失效后的处理、微信后台域名要求，以及本地 Docker/开发者工具的联调步骤。配置样例不包含真实凭证。

## 验证与完成条件

- API 测试覆盖未登录签发、未知应用、票据单次兑换、过期、跨应用、并发重放，以及 WebView JWT 与小程序 JWT 的双向隔离。
- 小程序测试覆盖登录返回、只允许登记应用、已有查询参数的 URL 拼接、成功坐标和所有定位失败状态；定位失败仍打开网页且不带任何坐标参数。
- 示例 H5 验证兑换、读取资料、从地址栏移除 ticket、缺票据和过期提示。全仓类型检查、相关测试、小程序构建和 API Docker 构建通过。
- 微信开发者工具检查页面、路由、示例联通；真机 HTTPS、业务域名、真实定位授权和外部业务网页接入在具备域名后验收，不把本地开发者工具结果当作正式环境验收。
